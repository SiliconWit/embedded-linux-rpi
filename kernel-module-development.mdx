Some work cannot be done by an ordinary program: answering an interrupt within a fixed time, writing to hardware registers, or giving every program on the board one shared device to open. That work belongs in the kernel, where a mistake can stop the whole board. A kernel module makes this work practical: it is driver code that you load into the running kernel and remove again, with no kernel rebuild and no reboot. In this lesson you write a module that creates the device file /dev/mydevice, answers open, read, write and ioctl calls on it, and blinks three LEDs in a pattern you send. You also give it a setting file under /sys (sysfs) and a status file under /proc (procfs). #KernelModule #CharacterDevice #LinuxDriver

## What We Are Building

<Card title="Custom Character Device Driver for LED Patterns" icon="star">
A loadable kernel module (.ko) that creates /dev/mydevice. Writing a pattern string (such as "101010") to the device sets the blink sequence of three LEDs on GPIO pins. Reading from the device returns the current pattern and the cycle count. A sysfs file controls the blink speed, and a procfs file shows driver statistics. A mutex (a lock that only one user can hold at a time) protects the shared data, and the module loads and unloads cleanly with insmod and rmmod.
</Card>

You need a Pi with Raspberry Pi OS, a network connection (for `scp` and `ssh`) and the 6.6 kernel you built. A module loads only into the exact kernel it was built against.

| Device node | /dev/mydevice (character device, dynamic major) |

| sysfs interface | /sys/class/mydevice/mydevice/blink_speed |
| procfs interface | /proc/mydevice_stats |
| GPIO outputs | GPIO17, GPIO27, GPIO22 (three LEDs) |

## Kernel Space vs Userspace

<InArticleAd />


Linux runs code in two separate areas so that one bad program cannot stop the machine. Ordinary programs, such as the doorbell monitor you built with libgpiod, run in userspace. The kernel runs in kernel space with no protection, and a module becomes part of the kernel.

<CardGrid>
  <Card title="Kernel space" icon="warning">
    - Full access to all hardware and memory
    - One read through a null pointer can cause a kernel panic (the whole system stops)
    - No C library: use the kernel's own functions (printk, kmalloc, copy_to_user)
    - No floating point by default
  </Card>
  <Card title="Userspace" icon="approve-check">
    - Each process has its own protected memory
    - A crash stops only that process
    - Full C library (printf, malloc, open)
    - Reaches hardware only by asking the kernel
    - Standard debugging tools (gdb, strace)
  </Card>
</CardGrid>

A module has no `main()`. The kernel calls one function when the module is loaded, and that function registers everything the module offers:

```text
  Loading: insmod mydevice.ko
  ──────────────────────────────────────────
  module_init()
    ├──► gpio_request()         claim GPIO pins
    ├──► alloc_chrdev_region()  device number
    ├──► cdev_add()             register fops
    ├──► class_create()
    └──► device_create()        /dev/mydevice
         │
         ▼
  Module running: programs can
  open, read and write /dev/mydevice
```

The kernel does not clean up after a module as it does after a program that ends. The exit function must give back every item itself, in the opposite order, as you take plates off a stack: the last one put on comes off first.

```text
  Unloading: rmmod mydevice
  ──────────────────────────────────────────
  module_exit()
    ├──► device_destroy()
    ├──► cdev_del()
    ├──► unregister_chrdev_region()
    └──► gpio_free()
```

A module with a bug can crash the whole system, so develop on a test board (your Pi Zero 2 W) and never on your PC. Keep the serial console connected: it shows the kernel panic message even when the system no longer answers.

A program uses the driver as it uses a file. Each call on the device file arrives at one function of the module:

```text
  One device file, four calls
  ──────────────────────────────────────────
  Program (userspace)        Module (kernel)
  ───────────────────        ───────────────
  open("/dev/mydevice") ───► fops.open()

  write(fd, "101010")   ───► fops.write()
                             copy_from_user()
                             store the pattern

  read(fd, buf, 64)     ───► fops.read()
                             copy_to_user()
                             pattern + count

  close(fd)             ───► fops.release()
```

## Module Skeleton

<InArticleAd />


Every kernel module needs an init function, an exit function, and a few macros that describe it. Start with a module that only writes one line to the kernel log each time.

Create a working directory on your host machine:

```bash
mkdir -p ~/rpi-kernel-modules/mydevice
cd ~/rpi-kernel-modules/mydevice
```

Create the module source file `mydevice.c`:

```c title="mydevice.c"
#include <linux/module.h>
#include <linux/init.h>
#include <linux/kernel.h>

static int __init mydevice_init(void)
{
    pr_info("mydevice: module loaded\n");
    return 0;  /* 0 = success, negative = error */
}

static void __exit mydevice_exit(void)
{
    pr_info("mydevice: module unloaded\n");
}

module_init(mydevice_init);
module_exit(mydevice_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("Your Name");
MODULE_DESCRIPTION("LED pattern character device driver");
MODULE_VERSION("1.0");
```

What to notice in this skeleton:

- `module_init()` and `module_exit()` tell the kernel which two functions to call.
- `__init` lets the kernel free the memory of the init function after it has run once.
- `pr_info` is the kernel's `printf`. Its text goes to the kernel log, which you read with `dmesg`.
- `MODULE_LICENSE("GPL")` is required. Without it the kernel marks itself as "tainted", and many kernel functions cannot be used by the module.

## The Out-of-Tree Makefile

<InArticleAd />


A module must be compiled with the same options and headers as the kernel it will join, or the kernel refuses to load it. So your Makefile hands the work to the kernel's own build system (Kbuild) in the kernel source folder you built earlier. "Out-of-tree" means that your source stays in its own folder: `-C` sends `make` to the kernel folder and `M=` tells it where your source is.

```makefile title="Makefile"
obj-m += mydevice.o

# Path to the cross-compiled kernel source tree
KERNELDIR ?= $(HOME)/rpi-embedded/rpi-linux

# Cross-compiler prefix (must match what you used to build the kernel)
CROSS_COMPILE ?= aarch64-linux-gnu-
ARCH ?= arm64

all:
	$(MAKE) -C $(KERNELDIR) M=$(PWD) ARCH=$(ARCH) CROSS_COMPILE=$(CROSS_COMPILE) modules

clean:
	$(MAKE) -C $(KERNELDIR) M=$(PWD) ARCH=$(ARCH) clean
```

Build the module:

```bash
cd ~/rpi-kernel-modules/mydevice
make
```

If the build succeeds, the directory contains `mydevice.ko`. The `.ko` extension means "kernel object". The file holds your compiled code and a description of it: its parameters, the modules it depends on, and the "version magic", the exact kernel version it was built for.

<Card title="Common Build Error" icon="warning">
`Module.symvers is missing` means that KERNELDIR does not point to a built kernel tree. Build the kernel once with `make modules` first.
</Card>

## Loading and Unloading

<InArticleAd />


Copy the module to the Pi and test it:

```bash
# Copy to the Pi
scp mydevice.ko pi@raspberrypi.local:~/

# SSH into the Pi
ssh pi@raspberrypi.local
```

<Steps>

1. **Load the module with insmod**

   ```bash
   sudo insmod mydevice.ko
   ```

   `insmod` loads exactly the file you specify. It does not resolve dependencies automatically.

2. **Verify it loaded**

   ```bash
   lsmod | grep mydevice
   ```

   The output lists `mydevice` with its size.

3. **Check the kernel log**

   ```bash
   dmesg | tail -5
   ```

   You should see: `mydevice: module loaded`

4. **Inspect module metadata**

   ```bash
   modinfo mydevice.ko
   ```

   This shows the license, author, description, version, and any parameters.

5. **Unload the module**

   ```bash
   sudo rmmod mydevice
   dmesg | tail -5
   ```

   You should see: `mydevice: module unloaded`

</Steps>

**insmod and modprobe:** `insmod` loads one `.ko` file by its path. `modprobe` takes a module name, searches `/lib/modules/$(uname -r)/`, and first loads the modules it depends on. Use `insmod` during development. For a product, install the module into the modules directory and run `depmod -a` so that `modprobe` can find it.

## Module Parameters

<InArticleAd />


A value fixed in the source needs a new build for each change. A module parameter is a variable that you set on the `insmod` command line. The `module_param()` macro declares the variable, its type, and the permissions of the file that shows it in sysfs.

Add these lines to `mydevice.c` after the includes:

```c
static int blink_speed_ms = 500;
module_param(blink_speed_ms, int, 0644);
MODULE_PARM_DESC(blink_speed_ms, "LED blink interval in milliseconds (default: 500)");
```

The third argument (`0644`) is the permission of that file: the owner can read and write, others can read. So root can also change the value while the module runs, through `/sys/module/mydevice/parameters/blink_speed_ms`.

Load with a custom value:

```bash
sudo insmod mydevice.ko blink_speed_ms=200
```

Read the current value:

```bash
cat /sys/module/mydevice/parameters/blink_speed_ms
```

Change it at runtime:

```bash
echo 100 | sudo tee /sys/module/mydevice/parameters/blink_speed_ms
```

## Character Device Registration

<InArticleAd />


A program cannot call a function inside the kernel, but it can open a file. So Linux shows a driver as a special file under `/dev`, and each file operation on it (open, read, write, close, ioctl) runs one function of the driver. A device that is read and written as a stream of bytes is a character device. To register one, you:

1. Get a device number. The major number identifies the driver and the minor number one device of that driver.
2. Fill a `cdev` structure, the kernel's record of a character device, with a table of your functions.
3. Create a device class and a device. The system service udev then creates the file `/dev/mydevice` for you.

In the first listing, look at the `file_operations` table at the end: it connects each file operation to one of your functions.

```c
#include <linux/cdev.h>
#include <linux/fs.h>
#include <linux/device.h>
#include <linux/uaccess.h>

#define DEVICE_NAME "mydevice"
#define CLASS_NAME  "mydevice"

static dev_t dev_number;          /* Holds major/minor */
static struct cdev mydevice_cdev;
static struct class *mydevice_class;
static struct device *mydevice_device;

/* File operations */
static int mydevice_open(struct inode *inode, struct file *filp)
{
    pr_info("mydevice: device opened\n");
    return 0;
}

static int mydevice_release(struct inode *inode, struct file *filp)
{
    pr_info("mydevice: device closed\n");
    return 0;
}

static ssize_t mydevice_read(struct file *filp, char __user *buf,
                             size_t count, loff_t *offset)
{
    /* Implementation below in full driver */
    return 0;
}

static ssize_t mydevice_write(struct file *filp, const char __user *buf,
                              size_t count, loff_t *offset)
{
    /* Implementation below in full driver */
    return count;
}

static const struct file_operations mydevice_fops = {
    .owner   = THIS_MODULE,
    .open    = mydevice_open,
    .release = mydevice_release,
    .read    = mydevice_read,
    .write   = mydevice_write,
};
```

The registration sequence in `mydevice_init`:

```c
/* 1. Allocate a dynamic major number */
ret = alloc_chrdev_region(&dev_number, 0, 1, DEVICE_NAME);

/* 2. Initialize the cdev and link file_operations */
cdev_init(&mydevice_cdev, &mydevice_fops);
mydevice_cdev.owner = THIS_MODULE;
ret = cdev_add(&mydevice_cdev, dev_number, 1);

/* 3. Create device class (visible in /sys/class/) */
mydevice_class = class_create(CLASS_NAME);

/* 4. Create device node (triggers udev to create /dev/mydevice) */
mydevice_device = device_create(mydevice_class, NULL, dev_number,
                                NULL, DEVICE_NAME);
```

`class_create()` takes only the class name since Linux 6.4, which fits the 6.6 kernel used in this course. On older kernels (6.3 and earlier, including the 6.1 LTS series) the call is `class_create(THIS_MODULE, CLASS_NAME)`.

The cleanup sequence in `mydevice_exit` reverses the order:

```c
device_destroy(mydevice_class, dev_number);
class_destroy(mydevice_class);
cdev_del(&mydevice_cdev);
unregister_chrdev_region(dev_number, 1);
```

**copy_to_user and copy_from_user:** The buffer pointer that a program passes to `read()` or `write()` is an address in that program's own memory. It may be wrong, so a driver never reads or writes through it directly. These two functions check the address, then copy the data. They return the number of bytes that could not be copied (0 on success).

## GPIO from Kernel Space

<InArticleAd />


Inside the kernel you cannot use libgpiod: it is for programs. The kernel has its own GPIO functions. This module uses the `gpio_*` family, which names a pin by one integer. These functions are the old interface. They still exist in the 6.6 kernel used in this course, but a new driver should use the descriptor interface (`gpiod_get()` and related calls from `<linux/gpio/consumer.h>`) with the pins described in the device tree.

The old numbers have one trap. They are global numbers: the base number of the GPIO chip plus the pin's offset on it. On the `rpi-6.6.y` kernel `gpiochip0` no longer starts at 0 but at 512, so GPIO17 is number 512 + 17 = 529. Check the base on your board with `sudo cat /sys/kernel/debug/gpio` and set `GPIO_BASE` at the top of the driver to match.

In the complete driver below, `setup_gpios()` claims each pin with `gpio_request()` and makes it an output. If one pin fails, it frees the pins it already claimed. `cleanup_gpios()` switches the LEDs off and frees the pins.

Each `gpio_request` claims the pin for this module alone, and fails if another driver or a program already holds it. A pin that is not freed stays claimed until the next reboot, so free the pins in the exit function and on every error path.

## The LED Pattern Driver

<InArticleAd />


The complete driver joins all the pieces. Two things in it are new.

**A mutex.** A program can write a new pattern while the blink step reads the old one, half replaced. So all code that touches the pattern first takes `pattern_mutex`, and sleeps while another holder has it.

**Delayed work.** The blink step must run every few hundred milliseconds. A kernel timer (`timer_list`) looks like the natural tool, but a timer callback runs in atomic context, where code is not allowed to sleep, so it must not take a mutex. Delayed work is a function that the kernel runs after a delay in a worker thread, where sleeping is allowed. Each run schedules the next one.

Read `blink_work_fn()` first, then the file operations, then `mydevice_init()`: its `goto` labels undo the completed steps in reverse order when a later step fails. Create this as `mydevice.c`:

```c title="mydevice.c" collapse={1-10}
/*
 * mydevice.c - LED Pattern Character Device Driver
 *
 * Drives three LEDs (GPIO17, GPIO27, GPIO22) in a configurable
 * blink pattern. Controlled via /dev/mydevice, with sysfs and
 * procfs interfaces.
 *
 * Target: Raspberry Pi Zero 2 W (BCM2710A1)
 */

#include <linux/module.h>
#include <linux/init.h>
#include <linux/kernel.h>
#include <linux/cdev.h>
#include <linux/fs.h>
#include <linux/device.h>
#include <linux/uaccess.h>
#include <linux/gpio.h>
#include <linux/workqueue.h>
#include <linux/jiffies.h>
#include <linux/mutex.h>
#include <linux/slab.h>
#include <linux/proc_fs.h>
#include <linux/seq_file.h>
#include <linux/string.h>

#define DEVICE_NAME   "mydevice"
#define CLASS_NAME    "mydevice"
#define MAX_PATTERN   64
#define PROC_NAME     "mydevice_stats"

/* GPIO pin assignments (BCM numbers) and the global number of the
 * first line of gpiochip0: 512 on rpi-6.6.y, see /sys/kernel/debug/gpio */
#define GPIO_BASE 512
#define GPIO_LED1 17
#define GPIO_LED2 27
#define GPIO_LED3 22
#define NUM_LEDS  3

static int gpio_leds[NUM_LEDS] = {
    GPIO_BASE + GPIO_LED1, GPIO_BASE + GPIO_LED2, GPIO_BASE + GPIO_LED3
};
static const char *gpio_labels[NUM_LEDS] = { "led1", "led2", "led3" };

/* Module parameter */
static int blink_speed_ms = 500;
module_param(blink_speed_ms, int, 0644);
MODULE_PARM_DESC(blink_speed_ms, "LED blink interval in ms (default: 500)");

/* Device state */
static dev_t dev_number;
static struct cdev mydevice_cdev;
static struct class *mydevice_class;
static struct device *mydevice_device;

/* Pattern state (protected by pattern_mutex) */
static DEFINE_MUTEX(pattern_mutex);
static char pattern_str[MAX_PATTERN] = "101010";
static int pattern_len = 6;
static int pattern_pos;
static unsigned long cycle_count;
static unsigned long load_time_jiffies;

/* Delayed work for LED blinking. It runs in process context,
 * so the callback is allowed to take the mutex. */
static struct delayed_work blink_work;

/* ----------------------------------------------------------------
 * GPIO helpers
 * ---------------------------------------------------------------- */
static int setup_gpios(void)
{
    int i, ret;
    for (i = 0; i < NUM_LEDS; i++) {
        ret = gpio_request(gpio_leds[i], gpio_labels[i]);
        if (ret) {
            pr_err("mydevice: GPIO %d request failed\n", gpio_leds[i]);
            goto err_free;
        }
        ret = gpio_direction_output(gpio_leds[i], 0);
        if (ret) {
            pr_err("mydevice: GPIO %d direction set failed\n", gpio_leds[i]);
            gpio_free(gpio_leds[i]);
            goto err_free;
        }
    }
    return 0;

err_free:
    while (--i >= 0)
        gpio_free(gpio_leds[i]);
    return ret;
}

static void cleanup_gpios(void)
{
    int i;
    for (i = 0; i < NUM_LEDS; i++) {
        gpio_set_value(gpio_leds[i], 0);
        gpio_free(gpio_leds[i]);
    }
}

static void set_leds_from_pattern(int pos)
{
    int i;
    /*
     * Pattern string is read three bits at a time.
     * Each character is '0' or '1'. If the pattern is shorter
     * than 3 * position, it wraps around.
     */
    for (i = 0; i < NUM_LEDS; i++) {
        int idx = (pos * NUM_LEDS + i) % pattern_len;
        int val = (pattern_str[idx] == '1') ? 1 : 0;
        gpio_set_value(gpio_leds[i], val);
    }
}

/* ----------------------------------------------------------------
 * Blink work callback (runs in a kernel worker thread)
 * ---------------------------------------------------------------- */
static void blink_work_fn(struct work_struct *work)
{
    mutex_lock(&pattern_mutex);
    if (pattern_len > 0) {
        set_leds_from_pattern(pattern_pos);
        pattern_pos++;
        if (pattern_pos * NUM_LEDS >= pattern_len) {
            pattern_pos = 0;
            cycle_count++;
        }
    }
    mutex_unlock(&pattern_mutex);

    /* Re-arm the delayed work */
    schedule_delayed_work(&blink_work, msecs_to_jiffies(blink_speed_ms));
}

/* ----------------------------------------------------------------
 * File operations
 * ---------------------------------------------------------------- */
static int mydevice_open(struct inode *inode, struct file *filp)
{
    pr_info("mydevice: device opened by pid %d\n", current->pid);
    return 0;
}

static int mydevice_release(struct inode *inode, struct file *filp)
{
    pr_info("mydevice: device closed\n");
    return 0;
}

static ssize_t mydevice_read(struct file *filp, char __user *buf,
                             size_t count, loff_t *offset)
{
    char tmp[MAX_PATTERN + 64];
    int len;

    mutex_lock(&pattern_mutex);
    len = snprintf(tmp, sizeof(tmp), "pattern: %s\ncycles: %lu\n",
                   pattern_str, cycle_count);
    mutex_unlock(&pattern_mutex);

    if (*offset >= len)
        return 0;

    if (count > len - *offset)
        count = len - *offset;

    if (copy_to_user(buf, tmp + *offset, count))
        return -EFAULT;

    *offset += count;
    return count;
}

static ssize_t mydevice_write(struct file *filp, const char __user *buf,
                              size_t count, loff_t *offset)
{
    char tmp[MAX_PATTERN];
    size_t written = count;  /* report every byte as consumed, newline included */
    int i;

    if (count == 0 || count >= MAX_PATTERN)
        return -EINVAL;

    if (copy_from_user(tmp, buf, count))
        return -EFAULT;

    /* Strip trailing newline */
    if (tmp[count - 1] == '\n')
        count--;

    if (count == 0)
        return -EINVAL;

    /* Validate: only '0' and '1' allowed */
    for (i = 0; i < count; i++) {
        if (tmp[i] != '0' && tmp[i] != '1')
            return -EINVAL;
    }
    tmp[count] = '\0';

    mutex_lock(&pattern_mutex);
    strncpy(pattern_str, tmp, MAX_PATTERN);
    pattern_len = count;
    pattern_pos = 0;
    mutex_unlock(&pattern_mutex);

    pr_info("mydevice: new pattern set: %s\n", pattern_str);
    return written;
}

/* ioctl command definitions */
#define MYDEVICE_MAGIC 'M'
#define MYDEVICE_RESET_CYCLES _IO(MYDEVICE_MAGIC, 0)
#define MYDEVICE_GET_CYCLES   _IOR(MYDEVICE_MAGIC, 1, unsigned long)
#define MYDEVICE_SET_SPEED    _IOW(MYDEVICE_MAGIC, 2, int)

static long mydevice_ioctl(struct file *filp, unsigned int cmd,
                           unsigned long arg)
{
    switch (cmd) {
    case MYDEVICE_RESET_CYCLES:
        mutex_lock(&pattern_mutex);
        cycle_count = 0;
        mutex_unlock(&pattern_mutex);
        pr_info("mydevice: cycle counter reset\n");
        return 0;

    case MYDEVICE_GET_CYCLES:
        mutex_lock(&pattern_mutex);
        if (copy_to_user((unsigned long __user *)arg,
                         &cycle_count, sizeof(cycle_count))) {
            mutex_unlock(&pattern_mutex);
            return -EFAULT;
        }
        mutex_unlock(&pattern_mutex);
        return 0;

    case MYDEVICE_SET_SPEED:
        if ((int)arg < 10 || (int)arg > 10000)
            return -EINVAL;
        blink_speed_ms = (int)arg;
        pr_info("mydevice: blink speed set to %d ms\n", blink_speed_ms);
        return 0;

    default:
        return -ENOTTY;
    }
}

static const struct file_operations mydevice_fops = {
    .owner          = THIS_MODULE,
    .open           = mydevice_open,
    .release        = mydevice_release,
    .read           = mydevice_read,
    .write          = mydevice_write,
    .unlocked_ioctl = mydevice_ioctl,
};

/* ----------------------------------------------------------------
 * sysfs attribute: blink_speed_ms
 * ---------------------------------------------------------------- */
static ssize_t blink_speed_show(struct device *dev,
                                struct device_attribute *attr, char *buf)
{
    return sprintf(buf, "%d\n", blink_speed_ms);
}

static ssize_t blink_speed_store(struct device *dev,
                                 struct device_attribute *attr,
                                 const char *buf, size_t count)
{
    int val;
    if (kstrtoint(buf, 10, &val))
        return -EINVAL;
    if (val < 10 || val > 10000)
        return -EINVAL;
    blink_speed_ms = val;
    pr_info("mydevice: blink_speed_ms set to %d via sysfs\n", val);
    return count;
}

static DEVICE_ATTR_RW(blink_speed);

/* ----------------------------------------------------------------
 * procfs: /proc/mydevice_stats
 * ---------------------------------------------------------------- */
static int mydevice_proc_show(struct seq_file *m, void *v)
{
    unsigned long uptime_sec;

    mutex_lock(&pattern_mutex);
    uptime_sec = (jiffies - load_time_jiffies) / HZ;
    seq_printf(m, "driver:       mydevice\n");
    seq_printf(m, "pattern:      %s\n", pattern_str);
    seq_printf(m, "pattern_len:  %d\n", pattern_len);
    seq_printf(m, "cycle_count:  %lu\n", cycle_count);
    seq_printf(m, "blink_speed:  %d ms\n", blink_speed_ms);
    seq_printf(m, "uptime:       %lu seconds\n", uptime_sec);
    seq_printf(m, "gpio_pins:    %d, %d, %d\n",
               GPIO_LED1, GPIO_LED2, GPIO_LED3);
    mutex_unlock(&pattern_mutex);
    return 0;
}

static int mydevice_proc_open(struct inode *inode, struct file *file)
{
    return single_open(file, mydevice_proc_show, NULL);
}

static const struct proc_ops mydevice_proc_ops = {
    .proc_open    = mydevice_proc_open,
    .proc_read    = seq_read,
    .proc_lseek   = seq_lseek,
    .proc_release = single_release,
};

/* ----------------------------------------------------------------
 * Module init and exit
 * ---------------------------------------------------------------- */
static int __init mydevice_init(void)
{
    int ret;

    load_time_jiffies = jiffies;

    /* 1. Set up GPIOs */
    ret = setup_gpios();
    if (ret)
        return ret;

    /* 2. Allocate character device region */
    ret = alloc_chrdev_region(&dev_number, 0, 1, DEVICE_NAME);
    if (ret) {
        pr_err("mydevice: alloc_chrdev_region failed\n");
        goto err_gpio;
    }

    /* 3. Initialize and add cdev */
    cdev_init(&mydevice_cdev, &mydevice_fops);
    mydevice_cdev.owner = THIS_MODULE;
    ret = cdev_add(&mydevice_cdev, dev_number, 1);
    if (ret) {
        pr_err("mydevice: cdev_add failed\n");
        goto err_region;
    }

    /* 4. Create device class */
    mydevice_class = class_create(CLASS_NAME);
    if (IS_ERR(mydevice_class)) {
        pr_err("mydevice: class_create failed\n");
        ret = PTR_ERR(mydevice_class);
        goto err_cdev;
    }

    /* 5. Create device node */
    mydevice_device = device_create(mydevice_class, NULL, dev_number,
                                    NULL, DEVICE_NAME);
    if (IS_ERR(mydevice_device)) {
        pr_err("mydevice: device_create failed\n");
        ret = PTR_ERR(mydevice_device);
        goto err_class;
    }

    /* 6. Create sysfs attribute */
    ret = device_create_file(mydevice_device, &dev_attr_blink_speed);
    if (ret) {
        pr_err("mydevice: sysfs attribute creation failed\n");
        goto err_device;
    }

    /* 7. Create procfs entry */
    if (!proc_create(PROC_NAME, 0444, NULL, &mydevice_proc_ops)) {
        pr_err("mydevice: proc_create failed\n");
        ret = -ENOMEM;
        goto err_sysfs;
    }

    /* 8. Start the blink work */
    INIT_DELAYED_WORK(&blink_work, blink_work_fn);
    schedule_delayed_work(&blink_work, msecs_to_jiffies(blink_speed_ms));

    pr_info("mydevice: loaded (major=%d, blink_speed=%d ms)\n",
            MAJOR(dev_number), blink_speed_ms);
    return 0;

err_sysfs:
    device_remove_file(mydevice_device, &dev_attr_blink_speed);
err_device:
    device_destroy(mydevice_class, dev_number);
err_class:
    class_destroy(mydevice_class);
err_cdev:
    cdev_del(&mydevice_cdev);
err_region:
    unregister_chrdev_region(dev_number, 1);
err_gpio:
    cleanup_gpios();
    return ret;
}

static void __exit mydevice_exit(void)
{
    cancel_delayed_work_sync(&blink_work);
    remove_proc_entry(PROC_NAME, NULL);
    device_remove_file(mydevice_device, &dev_attr_blink_speed);
    device_destroy(mydevice_class, dev_number);
    class_destroy(mydevice_class);
    cdev_del(&mydevice_cdev);
    unregister_chrdev_region(dev_number, 1);
    cleanup_gpios();
    pr_info("mydevice: unloaded\n");
}

module_init(mydevice_init);
module_exit(mydevice_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("Your Name");
MODULE_DESCRIPTION("LED pattern character device driver");
MODULE_VERSION("1.0");
```

## sysfs Interface

<InArticleAd />


sysfs is the directory `/sys`, where the kernel shows each device as a folder and each setting as a small file with one value. A user needs only `cat` and `echo`.

The driver creates one such file (an attribute) with `DEVICE_ATTR_RW(blink_speed)`. The macro expects two functions with fixed names, `blink_speed_show` for a read and `blink_speed_store` for a write, and connects them to the file `/sys/class/mydevice/mydevice/blink_speed`.

Read the current blink speed:

```bash
cat /sys/class/mydevice/mydevice/blink_speed
```

Change the blink speed at runtime:

```bash
echo 100 | sudo tee /sys/class/mydevice/mydevice/blink_speed
```

The store function accepts only an integer from 10 to 10000 milliseconds. Other values return an error:

```bash
# This will fail with "Invalid argument"
echo -1 | sudo tee /sys/class/mydevice/mydevice/blink_speed
```

## procfs Interface

<InArticleAd />


procfs is the directory `/proc`, where the kernel produces the text of a file at the moment it is read. sysfs is for single values. procfs suits a status report of several lines. The driver creates `/proc/mydevice_stats` with `proc_create` and the `seq_file` functions.

```bash
cat /proc/mydevice_stats
```

Expected output:

```
driver:       mydevice
pattern:      101010
pattern_len:  6
cycle_count:  42
blink_speed:  500 ms
uptime:       120 seconds
gpio_pins:    17, 27, 22
```

The `seq_file` functions manage the output buffer for you. This driver's output is small, so the simple form `single_open` and `single_release` is enough.

## ioctl Commands

<InArticleAd />


Some requests are not data: "reset the counter" is a command. The `ioctl` (input/output control) system call sends a command number, and one optional value, to a driver. The driver defines three commands:

| Command | Macro | Direction | Description |
|---------|-------|-----------|-------------|
| Reset cycles | `MYDEVICE_RESET_CYCLES` | None (`_IO`) | Resets the cycle counter to zero |
| Get cycles | `MYDEVICE_GET_CYCLES` | Read (`_IOR`) | Copies the cycle count to the program |
| Set speed | `MYDEVICE_SET_SPEED` | Write (`_IOW`) | Sets the blink speed in milliseconds |

The macros `_IO`, `_IOR` and `_IOW` build a command number from a letter chosen by the driver (`'M'`, the "magic number", which keeps the numbers apart from those of other drivers), a sequence number, and the direction and size of the value.

The test program reads the count, resets it, reads it again and sets the speed. It repeats the three `#define` lines of the module, because both sides must use the same numbers. Create this as `test_ioctl.c`:

```c title="test_ioctl.c"
#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/ioctl.h>

/* Must match the definitions in the kernel module */
#define MYDEVICE_MAGIC 'M'
#define MYDEVICE_RESET_CYCLES _IO(MYDEVICE_MAGIC, 0)
#define MYDEVICE_GET_CYCLES   _IOR(MYDEVICE_MAGIC, 1, unsigned long)
#define MYDEVICE_SET_SPEED    _IOW(MYDEVICE_MAGIC, 2, int)

int main(int argc, char *argv[])
{
    int fd;
    unsigned long cycles;
    int new_speed;

    fd = open("/dev/mydevice", O_RDWR);
    if (fd < 0) {
        perror("open /dev/mydevice");
        return 1;
    }

    /* Get current cycle count */
    if (ioctl(fd, MYDEVICE_GET_CYCLES, &cycles) < 0) {
        perror("ioctl GET_CYCLES");
        close(fd);
        return 1;
    }
    printf("Current cycle count: %lu\n", cycles);

    /* Reset the cycle counter */
    if (ioctl(fd, MYDEVICE_RESET_CYCLES) < 0) {
        perror("ioctl RESET_CYCLES");
        close(fd);
        return 1;
    }
    printf("Cycle counter reset.\n");

    /* Verify it was reset */
    if (ioctl(fd, MYDEVICE_GET_CYCLES, &cycles) < 0) {
        perror("ioctl GET_CYCLES");
        close(fd);
        return 1;
    }
    printf("Cycle count after reset: %lu\n", cycles);

    /* Set blink speed to 150ms */
    new_speed = 150;
    if (ioctl(fd, MYDEVICE_SET_SPEED, new_speed) < 0) {
        perror("ioctl SET_SPEED");
        close(fd);
        return 1;
    }
    printf("Blink speed set to %d ms\n", new_speed);

    close(fd);
    return 0;
}
```

Cross-compile and run it:

```bash
# On host
aarch64-linux-gnu-gcc -o test_ioctl test_ioctl.c
scp test_ioctl pi@raspberrypi.local:~/

# On the Pi
sudo ./test_ioctl
```

Expected output:

```
Current cycle count: 42
Cycle counter reset.
Cycle count after reset: 0
Blink speed set to 150 ms
```

In a real project, put the ioctl definitions in one header file that both the kernel module and the programs include, so the numbers cannot drift apart.
